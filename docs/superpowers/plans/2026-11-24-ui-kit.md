# UI Kit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `src/lib/ui/*` — accessible components on bits-ui and semantic OKLCH tokens, ready for screen migration.

**Architecture:** Each component is a separate `.svelte` file with `$props()`; `tv()` recipes live next to the component in `<script module>`; bits-ui handles accessibility and keyboard support, while styling uses only tokens from `src/app.css`. There is no barrel or shared `variants.ts` — import directly from `.svelte` files.

**Tech Stack:** Svelte 5 runes, bits-ui 2.22.0, tailwind-variants 4.0.2, Tailwind v4, Bun.

**Spec:** `docs/superpowers/specs/2026-11-24-ui-kit-design.md`

## Global Constraints

- Bun only, exact versions; `bun run validate` is the gate for each task.
- Svelte 5 runes, `$props()`, keyed `{#each}`, `$bindable()` where needed; no legacy syntax.
- Only semantic tokens from `src/app.css`; no hex or raw colors.
- UI strings in English; code/comments/identifiers in English.
- Do not touch `src/App.svelte`, `src/lib/components/*`, engine/archive/sync/server (that is a separate migration).
- No new dependencies: bits-ui and tailwind-variants are already installed.
- `bun x @sveltejs/mcp svelte-autofixer` on all new `.svelte` files — 0 issues.

## Review Focus

1. Contrast of `text-on-accent` on all accent variants and `text-danger` on `bg-danger-soft` in both themes → browser smoke.
2. A visible focus indicator (ring-focus) on button/switch/tabs/dialog/input/textarea → browser smoke + autofixer.
3. bits-ui accessibility: ARIA `aria-checked`, `aria-selected`, `role=alert`, desktop keyboard navigation → browser smoke.
4. No raw colors and no accidental changes to other subsystems → `git diff` + validate.
